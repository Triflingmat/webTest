# 任务：开发基于 Vue 3 + TypeScript + Vite + ECharts 的工会综合数据看板

## 一、角色设定

你是一名资深前端开发工程师和数据可视化设计师，熟悉 Vue 3、TypeScript、Vite、ECharts、CSS 布局、组件化开发及数据大屏设计。

请从实际项目开发的角度完成本任务，不仅要生成静态页面，还要确保页面结构合理、图表配置正确、代码可维护、项目可以运行。

## 二、项目目标

开发一个工会综合数据看板页面，集中展示思想引领、就业概况、用户地区分布、工会活动、用户类型、劳模工匠、工会组织及积分发放等业务数据。

页面包含以下 7 个主要模块：

1. 思想引领与就业概况
2. 阅读用户地区分布
3. 工会活动
4. 用户类型
5. 劳模工匠
6. 工会组织
7. 积分发放

整体采用现代化的数据看板设计风格，注重信息层级、图表可读性、模块间距和视觉统一性。页面应适合在桌面浏览器中展示，同时兼顾常见笔记本屏幕尺寸。

## 三、技术栈与开发约束

### 3.1 技术栈

- Vue 3
- TypeScript
- Vite
- ECharts
- HTML5
- CSS3

使用 Vue 3 Composition API 和 `<script setup lang="ts">` 编写组件。

使用 ECharts 实现全部指定的数据图表，不得用普通 CSS 图形、静态图片或手绘 SVG 代替指定图表。

如项目已经存在，请优先沿用项目已有的依赖、目录结构和编码规范，不要随意重建项目或升级依赖。

如当前目录为空，再初始化 Vue 3 + TypeScript + Vite 项目并安装必要依赖。

### 3.2 开发原则

1. 采用组件化开发，避免将所有页面、数据和图表逻辑堆积在一个文件中。
2. 所有图表数据使用独立的数据结构维护，方便后续接入后端 API。
3. 通过 TypeScript 类型定义约束数据结构。
4. 图表配置应尽可能复用公共逻辑，但不能为了抽象而降低可读性。
5. 不引入与本项目无关的第三方依赖。
6. 所有模拟数据必须与真实业务数据区分，不得虚构数据来源。
7. 页面中的标题、统计数值、图例、表格内容必须完整显示，避免重叠、截断和错位。

## 四、页面整体设计要求

### 4.1 页面布局

采用数据看板布局，整体由页面标题区域和数据模块区域组成。

建议页面结构：

- 顶部：页面标题、简短说明或统计口径提示。
- 第一行：思想引领、就业概况两个统计模块。
- 第二行：阅读用户地区分布、工会活动、用户类型。
- 第三行：劳模工匠、工会组织、积分发放。

根据实际屏幕宽度合理调整模块比例和高度，优先保证信息展示完整。如果三列布局导致图表拥挤，可以适当调整列宽或使用更合理的栅格布局，但不能随意遗漏模块。

### 4.2 视觉规范

整体采用简洁、专业、现代的政务数据可视化风格。

- 使用统一的页面背景、模块卡片背景、圆角、边框和阴影规范。
- 每个模块具有清晰的标题区域和内容区域。
- 采用统一的字体、字号、间距和颜色体系。
- 统计指标突出显示数值，同时保持标签清晰。
- 图表颜色协调、区分明确，避免过度使用渐变、发光和装饰效果。
- 图例、坐标轴、标签及表格内容必须具有足够的对比度。
- 不使用无实际意义的大量装饰元素影响数据阅读。
- 不要使用 Emoji 代替正式图标。
- 如果没有现成设计稿，可自行确定一套完整的设计规范，并在所有模块中保持一致。

### 4.3 响应式布局

使用 CSS Grid、Flexbox 或合理的组合实现布局。

- 桌面端优先采用多列数据卡片布局。
- 窄屏时根据空间调整列数、卡片宽度和图表高度。
- 页面不能因为固定宽度造成严重横向溢出。
- 图表必须在容器尺寸变化后正确调整大小。
- 不得通过将整个页面无限缩小来实现响应式适配。

## 五、7 个模块的具体实现要求

### 模块 1：思想引领与就业概况

该模块由两组独立的统计卡片组成。

**思想引领：**

展示以下 4 项指标：

1. 文章发布数
2. 阅读量
3. 文章采纳数
4. 点赞量

**就业概况：**

展示以下 4 项指标：

1. 发布岗位
2. 求职人数
3. 促进就业
4. 招聘活动

实现要求：

- 使用 Flex 布局，每组包含 4 张统计卡片。
- 两组统计内容应清晰区分，具有独立的组标题。
- 每张卡片包含指标名称、统计数值及必要的单位。
- 数值使用较明显的字号和字重。
- 卡片宽度、内边距、间距和高度保持协调。
- 数值较大时可以使用千分位分隔符。
- 不同指标可以采用协调的辅助色，但不能破坏整体视觉统一性。
- 窄屏下允许换行，避免卡片内容挤压。

### 模块 2：阅读用户地区分布

使用 ECharts 横向柱状图，展示不同地区的阅读用户数量。

实现要求：

- 图表类型为横向柱状图。
- 使用 `xAxis.type = 'value'` 和 `yAxis.type = 'category'` 实现横向柱状图。
- 每个地区对应一条柱体。
- 展示地区名称、阅读人数和对应柱体。
- 柱体长度必须与对应数值成比例，不能使用与数据不一致的视觉长度。
- 在柱体末端展示数值标签。
- 合理配置类目轴顺序、坐标轴刻度、网格线和标签位置。
- 根据数据量合理控制图表高度和类目间距。
- 数据标签不能与图表边界发生明显重叠。
- 使用明确的单位，例如“人”。

### 模块 3：工会活动

使用表格展示工会活动信息。

表格包含以下 4 列：

1. 排名
2. 活动名称
3. 分类
4. 参与人次

实现要求：

- 表头与每行内容严格对齐。
- 各列具有合理的宽度分配。
- 排名列和参与人次列应清晰易读。
- 活动名称较长时允许合理截断或换行，但不能影响其他列。
- 表格行高、字体、边框和间距保持统一。
- 可以使用轻量化的隔行背景或悬停效果增强可读性。
- 参与人次应使用明确的单位。
- 数据较多时，内容区域可以独立滚动，但模块标题应保持稳定。
- 不要为了展示效果而让表头和内容使用两套不一致的宽度。

如果没有指定 UI 组件库，优先使用原生 HTML 表格配合 CSS 实现，避免为单个表格引入不必要的依赖。

### 模块 4：用户类型

使用 ECharts 实现带间隔的环形饼图，展示不同用户类别的数量。

实现要求：

- 使用 `series.type = 'pie'` 实现环形饼图。
- 设置 `radius` 为内外半径组成的数组，形成清晰的环形结构。
- 通过 `padAngle` 或适当的边框间距，使扇区之间具有明确的间隙；如果当前 ECharts 版本不支持相关配置，则使用兼容方案实现。
- 各类别通过不同颜色区分。
- 提供完整的图例，包含用户类别和对应颜色。
- 通过图例或提示框展示类别、数量及必要的占比信息。
- 根据模块宽度合理安排图表与图例的位置。
- 避免图例遮挡图表。
- 不得让各扇区的大小与实际数据比例不一致。
- 如使用中心文字展示总用户数，必须确保它与数据总和一致。

### 模块 5：劳模工匠

使用 ECharts 极坐标柱状图，展示不同级别的劳模工匠数据。

包含以下 4 个类别：

1. 县级
2. 市级
3. 省级
4. 国家级

实现要求：

- 使用 ECharts 极坐标系及柱状系列实现。
- 使用 `polar`、`angleAxis`、`radiusAxis` 等必要配置。
- 四个类别应对应清晰、正确的角度轴类目。
- 每个类别使用明确的数据值。
- 通过颜色区分不同级别，并提供对应图例。
- 图例颜色必须与对应圆弧或柱体颜色一致。
- 极坐标柱体的长度必须反映实际数值。
- 合理配置极坐标的内外半径、角度轴标签和柱体间距。
- 避免类别名称与图形重叠。
- 图表必须具备清晰的数值含义，不得仅为了视觉效果随意配置数据映射。
- 如果采用自定义的多系列方案实现分级配色，必须确保图例、系列名称、类别和值之间的映射关系正确。

### 模块 6：工会组织

使用 ECharts 玫瑰图展示不同类型工会组织的数量。

包含以下 4 个类别：

1. 村社工会
2. 其他
3. 企业
4. 事业单位

实现要求：

- 使用 `series.type = 'pie'`。
- 使用 `roseType = 'radius'`，通过扇区半径体现数值差异。
- 每个类别采用清晰、协调且可区分的颜色。
- 提供类别图例及对应颜色。
- 鼠标悬停时展示组织类型、数量和必要的占比信息。
- 正确处理类别名称、图例和数据之间的映射。
- 避免扇区标签与图例相互遮挡。
- 玫瑰图必须体现半径差异，不能只实现普通等半径环形图。

### 模块 7：积分发放

使用 ECharts 竖向柱状图展示不同类型的积分发放数量。

实现要求：

- 使用普通笛卡尔坐标系柱状图。
- 横轴展示积分发放类型名称。
- 纵轴展示积分数量。
- 使用柱体末端标签显示具体数值。
- 纵轴名称、提示框及标签应明确说明计量单位，例如“积分”。
- 类别较多或名称较长时，应适当旋转标签、换行或调整网格边距。
- 柱体宽度、间距、颜色和圆角保持协调。
- 坐标轴范围应与实际数据匹配，避免误导性展示。
- 鼠标悬停时显示类型名称、数值和单位。

**选做功能：月度视图**

如果实现月度视图：

- 提供“类型视图”和“月度视图”之间的切换入口。
- 默认进入类型视图。
- 切换后更新图表数据、横轴类别和必要的标题。
- 切换控件必须真实可用，不能仅展示按钮而不实现交互。
- 两种视图应使用统一的图表样式和单位规则。
- 如果缺少真实月度数据，可以使用明确标记的模拟数据，不能伪装成真实业务统计。

- 公共图表组件可封装 ECharts 初始化、实例更新、尺寸调整和销毁逻辑。
- 模拟数据和类型定义独立维护。
- 不要为了复用而将差异较大的图表强行塞进一个难以维护的巨型组件。

## 八、ECharts 生命周期与工程质量

所有图表组件必须正确处理 ECharts 实例生命周期。

要求：

1. 在组件挂载且容器可用后初始化图表。
2. 数据或配置发生变化时，使用合理的方式更新图表。
3. 页面尺寸变化时，使用 ResizeObserver 或适当的窗口尺寸监听机制调整图表大小。
4. 在组件卸载时销毁 ECharts 实例并清理相关监听器。
5. 避免重复初始化造成内存泄漏。
6. 避免 DOM 容器尺寸为零时初始化导致的异常。
7. 为图表容器设置合理的最小高度和明确的布局约束。
8. 使用模块化导入时，确保正确注册所需的 ECharts 图表、组件和渲染器。
9. 不允许出现控制台持续报错、图表空白或因尺寸变化导致的明显布局异常。
